# Deployment

This runbook deploys the first production environment for Personal Album.

## Production Shape

- Region: `ap-southeast-2` for the stack.
- Public app: `https://album.joe-cui.com`.
- TLS certificate: existing ACM certificate in `us-east-1` that covers `album.joe-cui.com`.
- API: default HTTP API invoke URL generated by CDK.
- Web hosting: private S3 web asset bucket behind CloudFront.
- Photos: private S3 photos bucket; Display Photos are generated but not publicly served in Phase 5.

## Prerequisites

1. Configure AWS credentials for the target production account.
2. Use Node.js 22 or newer.
3. Verify the Route 53 hosted zone for `joe-cui.com`.
4. Create or confirm a `us-east-1` ACM certificate for `album.joe-cui.com`.
5. Verify the SES identity for `joe-cui.com`.
6. If SES is still sandboxed, verify every Allowed User recipient email address.
7. Prepare non-private smoke test photos: one JPEG, one PNG, and one real HEIC.

## Local Environment

Create `.env` at the repo root. Do not commit it.

```sh
USER_ALLOWLIST=dad:dad@example.com,mum:mum@example.com
BUDGET_ALERT_EMAIL=you@example.com
SESSION_SIGNING_SECRET=replace-with-a-long-random-secret
SES_FROM_EMAIL=album@joe-cui.com
ALLOW_DEV_AUTH_CODES=false
ALBUM_DOMAIN=album.joe-cui.com
HOSTED_ZONE_DOMAIN=joe-cui.com
HOSTED_ZONE_ID=Z00000000000000000000
CERTIFICATE_ARN=arn:aws:acm:us-east-1:123456789012:certificate/example
AWS_REGION=ap-southeast-2
```

For local browser testing against the cloud API, add:

```sh
ADDITIONAL_WEB_ORIGINS=http://localhost:5173
```

Production should normally leave `ADDITIONAL_WEB_ORIGINS` empty so CORS only allows `https://album.joe-cui.com`.

## Deploy

Run:

```sh
npm run deploy
```

The script:

1. Loads `.env` if present.
2. Runs workspace type checks.
3. Deploys `PersonalAlbumStack`.
4. Reads the CDK outputs for API URL, web bucket, and CloudFront distribution.
5. Builds the Vite SPA with `VITE_API_BASE_URL` set to the HTTP API URL.
6. Syncs `apps/web/dist` to the web bucket.
7. Invalidates CloudFront.

The script stops on failure and does not roll back, destroy, or clean up deployed resources.

## Smoke Test

1. Open `https://album.joe-cui.com`.
2. Request a sign-in code for an Allowed User email.
3. Confirm the code arrives through SES.
4. Verify sign-in succeeds and the page remains signed in after refresh.
5. Upload the prepared JPEG, PNG, and real HEIC files.
6. Confirm each file reaches `Ready`.
7. Upload one duplicate file and confirm it reaches `Exact duplicate`.
8. Confirm the CloudWatch alarms and budget subscription email confirmations have been acknowledged.

Keep smoke test photos in production temporarily under the chosen Allowed User's Personal Album. Do not manually delete S3 or DynamoDB records during the first deployment.
