# Use the Upload-Local Calendar for Captured At Fallbacks

When EXIF does not provide Captured At, file-modified and upload-time fallbacks will use the local calendar value seen by the uploading browser. The original absolute file-modified and upload-requested instants remain stored separately, but the browser's offset will not become Capture Time Offset because the upload location is not reliably the capture location. This avoids placing fallback Photos according to UTC while keeping the approximation visible through Captured At Source and correctable through Adjust Captured At.

The v2 Upload Batch request will provide one validated IANA upload-context time zone. The server will combine it with each authoritative file-modified instant and its own upload-requested instant, persist the resulting local calendar values plus their original instants and context zone, and never recompute Timeline placement during reads. This avoids trusting the browser clock or duplicating local strings for every file while keeping upload context distinct from capture-offset evidence; old clients use the explicit v1 compatibility contract rather than silently falling back to server time.
