# Use React Router with a Separate Browsing Window Controller

The web client will adopt React Router Data Mode for route matching, browser history, location state, navigation cancellation, and route-level failures. Its contextual or masked-location support will implement the stable Photo Viewer URL over a retained Timeline or Archive route, while a direct Viewer URL renders independently. Each browser history entry carries an opaque Browsing Window instance key in serialisable history state; collection and `startAt` remain URL-derived creation configuration and never serve as instance identity. Back and Forward use the opaque key to recover a retained instance, while refresh or an evicted key recreates from the URL. Cursor pages, Justified Row layout, virtualisation, Thumbnail Access leases, and restoration anchors remain in a dedicated Browsing Window controller rather than router loader state, and the app will not introduce a custom history object or use generic pixel scroll restoration for the virtualised collection. This adds one routing dependency while avoiding a hand-built history system and keeping browsing mechanics replaceable beneath the route seam.
