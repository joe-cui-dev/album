# Subscribe to Controller Instances with React Built-Ins

Browsing Window and Photo Viewer modules will expose stable `getSnapshot`, `subscribe`, intent, and `dispose` interfaces consumed through React's `useSyncExternalStore`, without adding an application-wide Redux or Zustand store. Browsing Window's UI-facing commands are narrower still: one viewport observation, one lease-revisioned thumbnail outcome observation, and one semantic collection Retry intent. React does not command page loads, access acquisition or renewal, anchor recording, or lifecycle. A small Session and history registry composition root owns controller instances; the history registry is the only caller that activates, deactivates, or disposes a Browsing Window, while React mount and unmount only attach or detach UI adapters. React Router location state carries only an opaque per-history-entry Browsing Window instance key and serialisable route context, never cursor pages, Photo descriptors, restoration state, or temporary access. Controllers receive their owned ports at construction and do not import the global HTTP client. Browsing Window snapshots expose render-ready layout rather than internal descriptor, withholding, or access maps; structural sharing preserves unchanged layout items and replaces only rows affected by layout or access changes. Stable snapshot references isolate thumbnail and viewport updates from the full descriptor set while keeping state ownership local to each browsing or viewing lifecycle.
