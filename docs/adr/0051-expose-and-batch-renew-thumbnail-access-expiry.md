# Expose and Batch-Renew Timeline Thumbnail Access Expiry

Timeline page and Timeline Thumbnail Access responses will expose a conservative `expiresAt` for their temporary thumbnail URLs. One client scheduler will batch up to 100 visible or soon-visible Photo IDs for renewal shortly before expiry, coalesce concurrent demand for the same Photo, and replace both responsive sources together. It is an event-driven one-shot deadline scheduler rather than a fixed polling interval: demand, lease, backoff, connectivity, visibility, activation, and deactivation changes recompute the earliest next wake-up. Browser clock, timer, connectivity, and visibility form an internal seam with a production browser adapter and a deterministic test adapter; they do not expand the Browsing Window's external interface. Offline is a suspension rather than a failure: the scheduler starts no access or renewal request while offline, retains unexpired leases, and automatically re-evaluates current demand when connectivity returns. A request cancelled or rejected across the offline transition does not consume a Photo's recovery attempt. A hidden document is a lighter suspension of the still-active Browsing Window: no new prefetch, collection read, access request, or renewal begins, but in-flight requests may settle into the current lifecycle generation and existing demand and leases remain retained. When visible returns, expired access is discarded before the module batches current demand and resumes its one-shot schedule. The Browsing Window owns access-failure and automatic-recovery state, keyed by Photo ID and lease revision so a late failure from an older URL cannot affect newer access. The image UI adapter reports load outcomes and retains only presentation state such as decode fade. A first access or loading failure may trigger one immediate renewal and retry to recover from clock skew or early invalidation; a second failure for the renewed access becomes a local static cell placeholder rather than an infinite refresh loop, a collection-level failure, or a per-Photo User retry. Raw access exceptions remain internal. This adds an explicit lease signal to the API while keeping thumbnail bytes on the existing private presigned-download path.
