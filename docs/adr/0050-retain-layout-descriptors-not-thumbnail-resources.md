# Retain Layout Descriptors, Not Thumbnail Resources

One Browsing Window will retain a compact descriptor for every Photo it has incrementally loaded so reverse scrolling, row geometry, and restoration do not require a new newer-direction pagination API. A compact descriptor never contains a temporary Timeline Thumbnail URL. The Browsing Window retains temporary Thumbnail Access for active demand plus a count-bounded least-recently-used lease cache; active demand includes visible, soon-visible, and focus-pinned rows and cannot be evicted, while the least recently needed non-demand access is discarded when the cache reaches its measured limit. Rendered DOM, decoded image resources, request state, and temporary Timeline Thumbnail URLs therefore remain bounded independently of the number of loaded descriptors, and distant URLs are refreshed in batches when their Photos approach the viewport again. The cache limit is calibrated through the 20,000-Photo validation rather than encoded as a product invariant. That validation must measure the worst case where all compact descriptors have accumulated. A reverse-pagination or descriptor-eviction design will be reconsidered only if that measured footprint exceeds the agreed browser budget.
