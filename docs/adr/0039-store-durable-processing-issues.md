# Store Durable Processing Issues

Each Photo that first enters Processing Failed will transactionally create one per-User Processing Issue item and increment an exact open-count summary rather than relying on a scan of Photo records. Retry keeps the same Issue open with a retrying status, and subsequent failure updates it without changing its identity or list position. Becoming Ready or discovering an Exact Duplicate both transactionally remove the Issue and decrement the count: the latter needs no further User action, does not create a Timeline projection, and may link to the matching Ready Photo. The cursor-paginated Issue projection contains only User-facing reason codes and lightweight row data; infrastructure diagnostics remain in logs, while the summary lets navigation appear correctly without loading the Issue list.
