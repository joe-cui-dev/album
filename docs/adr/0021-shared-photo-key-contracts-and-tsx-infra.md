# Keep Photo Object Key Contracts in One Shared Module

The photo object key formats (`originals/{userId}/{uploadBatchId}/{photoId}`, `display/{userId}/{photoId}.jpg`, `timeline-thumbnails/{userId}/{photoId}.jpg`) and the S3 upload-metadata cross-check from ADR-0012 (`user-id` / `upload-batch-id` / `photo-id`) will be built and parsed by a single `photo-keys` module in `packages/shared`. Handlers must not hand-assemble these strings: building and matching live beside each other, so round-trip tests (`parse(build(x)) = x`, `matches(buildMetadata(x), x)`) are the contract tests, and a format change is one edit instead of a silent four-way drift between create-upload-batch, shared, infra, and the photo processor.

The existing Timeline Thumbnail key remains the canonical Small variant, and the Large variant extends it as `timeline-thumbnails/{userId}/{photoId}-large.jpg`. The v2 Photo and Timeline projection contracts group both keys and dimensions under explicit `small` and `large` variants, while the legacy flat Small fields remain read-compatible only during migration. This reuses every valid existing Small object and keeps variant selection semantic rather than naming Large as a device-specific `@2x` asset.

The infra stack consumes the same `ORIGINALS_KEY_PREFIX` constant for its S3-to-SQS notification filter. To make that import possible, the CDK app now runs TypeScript directly through `tsx` (`cdk.json` invokes `src/bin/album.ts`; the tsc-emit build step is gone and `@album/shared` stays a source-only package). We considered giving shared a real `dist` build — rejected because the web app's Vite dev loop consumes shared sources directly and would need a rebuild on every change — and keeping an infra literal locked only by assertions — rejected because infra-side edits would still drift unguarded.

All S3 access for photo objects goes through a `PhotoObjectStore` seam with two adapters (S3, in-memory fake), owning the presign TTLs (300-second downloads, config-driven uploads) and `Content-Disposition` sanitization. Both presign methods return `{url, expiresInSeconds}` so response bodies never invent their own expiry numbers.
