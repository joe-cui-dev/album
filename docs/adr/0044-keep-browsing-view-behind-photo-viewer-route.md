# Keep the Browsing View Behind the Photo Viewer Route

When a User opens Photo Viewer from Timeline or Archive, the web client will push the stable `/album/photos/{photoId}` route while keeping the originating browsing view mounted beneath a full-screen Darkroom layer. Browser Back therefore closes Viewer into the exact in-memory pagination, virtualisation, and scroll state instead of reconstructing that state from coordinates. A directly loaded or refreshed Viewer route renders as a standalone view; Close returns to the Photo's current Timeline or Archive collection, but does not claim to restore browsing history that never existed. This hybrid route model costs some retained client memory while Viewer is open, in exchange for reliable history semantics and immediate position restoration.
